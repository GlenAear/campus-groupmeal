# 项目技术选型分析

> 记录本项目"做什么、为什么这么选"的判断依据与结论。定案 2026-09-17；2026-11-04 改写为客观表述并补充技术选型对照（v1.1）。

## 1. 出发点：让课程与项目共用一份代码

课本《JSP 网站开发项目化教程》整本书就是一个**网上订餐系统**，12 个项目正好构成一条后端成长链：

| 课本项目 | 内容 | 对应到 Spring Boot 主工程的哪一层 |
|---|---|---|
| 项目一/二 | JSP 环境搭建、静态登录/注册页、JS 校验 | 前端静态页 → 后期 Vue3 看板 |
| 项目三/四 | Servlet 逻辑验证、session 存登录用户 | 登录/鉴权 → JWT |
| 项目五/六 | cookie 免重复登录、application 计数 | 记住我、访问统计 → 统计看板 |
| 项目七 | SmartUpload 图片上传 | 文件服务模块 |
| 项目八 | 实体类 / JavaBean / MVC 架构 / ArrayList 存记录 | entity ＋ 分层骨架 |
| 项目九~十二 | T-SQL、JSP 连库、登录查库、增删改查 | **MyBatis mapper ＋ service** |

由此得到选型的第一条标准：**能让平时作业、两次实验报告、期末大作业和自选项目落在同一个代码库上的方向，总成本最低**；需要为课程单独维护另一份代码的方向，等于双线并行。

## 2. 三个候选方向（五维评分，1–5）

| 维度 | A 校园拼单订餐＋智能取餐柜 | B 自习室/实验室座位预约＋能耗看板 | C 校园互助社区（失物/二手/任务） |
|---|---|---|---|
| 课程任务复用度 | **5**（业务域与课本完全一致，零额外作业） | 4（登录/预约/查改能覆盖，上传、计数等章节要硬凑） | 2（课本无社区/消息模块，作业需另做） |
| 题材新颖度 | 3.5（订餐不新，"拼单成团＋取餐柜"新） | 4 | 4.5 |
| 软硬件结合可行性（V2） | **4.5**（柜门开锁、叫号、保温计时，嵌入式有天然落点） | **5**（座位占用传感、能耗采集） | 2 |
| AI 拓展可行性（V3） | 4（拼单推荐、客服问答、口味/营养推荐） | 3.5（自习时长分析、推荐座位） | 4 |
| 可展示性（技术演进线是否完整） | **4.5**（"课程作业 → 完整系统 → 软硬一体"一条线讲得通） | 4 | 3 |
| **合计** | **21.5** | 21.5 | 15.5 |

A 与 B 总分持平，**决胜维度是课程复用度**：A 允许所有课程产出直接写进主工程；B 需要为课程额外维护一份订餐代码。

## 3. 结论：选 A

**一句话定位**：宿舍楼下的"拼好饭"——同楼用户拼单达到起送门槛后合并下单食堂/周边商家，成团后统一配送到**智能取餐柜**，扫码或刷卡取餐。

新颖点不在"订餐"本身，而在三处：

1. **拼单成团**（凑起送门槛、成团倒计时、未成团退款）——课本没有的业务逻辑，也是并发与状态机练习的天然载体；
2. **智能取餐柜**（格口分配、开锁、叫号、保温计时）——V2 阶段接 ESP32，是物联网专业的差异化落点；
3. **成团算法与推荐**（拼单推荐、客服问答）——V3 阶段的 AI 拓展空间。

**B 作为备选保留**：若后续需要更强的"纯硬件叙事"，座位预约＋能耗看板的传感部分得分更高，代价是课程作业要另养一个代码库。
**C 直接排除**：课程复用度只有 2 分，意味着同一学期维护两个互不相干的代码库。

## 4. 演进路线

| 版本 | 范围 | 技术重点 |
|---|---|---|
| V1 | 拼单成团 ＋ 取餐柜格口分配（纯软件，可演示） | Spring Boot 3 ＋ MyBatis ＋ MySQL；事务与状态机 |

## 5. 技术选型对照（练习形态 → 主工程形态）

本仓库当前的练习代码里有几处是**教学形态**，主工程会换掉，先把对照关系写清楚，免得日后误当作既定设计：

| 关注点 | 现在的练习代码（JSP/Servlet、MyBatis 重现工程） | 主工程 `groupmeal-server/` 的做法 | 为什么这样过渡 |
|---|---|---|---|
| 数据库访问 | `Conn` 类手写 JDBC ＋ `UsersDao` 拼 SQL；MyBatis 侧手写 mapper | MyBatis-Plus ＋ `@Mapper` 接口 | DAO 层的职责不变，变的只是"谁生成实现" |
| 连接参数 | 外置 `jdbc.properties`（已 `.gitignore`），仓库只留 `.example` | `application.yml` ＋ 环境变量／配置中心 | 口令任何时候都不进源码、不进版本库 |
| 口令存储 | `users.passwd` 存明文（课本原样） | **BCrypt 哈希 ＋ 盐**，页面与接口一律不查询、不回显该列 | 明文存储是教学简化，不能带进真实项目 |
| 页面展示名单 | `UsersDao.selAllNoPwd()`：SQL 里干脆不 `select passwd` | 同一条规则前置到 DTO/VO 层 | 敏感字段的第一道防线是"不查它"，而不是"查出来再打码" |
| 会话与鉴权 | `session.setAttribute("loginUser", ...)`；管理员＝用户名等于 `admin` | JWT ＋ 拦截器 ＋ 角色表 | 管理员判定不能靠字符串比较 |
| 查询条件 | `LIKE concat('%',?,'%')`（PreparedStatement 占位） | MyBatis 动态 SQL `<if>` ＋ 同样的 `?` 绑定 | 任何情况下不拼接 SQL 字符串 |
| 分页 | `selpage.jsp` 手写 `limit ?, ?` | PageHelper 插件 ＋ 统一 `PageResult<T>` | 同一个知识点的手写版与框架版 |
| 字符集/时区 | 表与连接统一 utf8mb4；URL 带 `serverTimezone=Asia/Shanghai` | 同一套规范 | MySQL 8.4 默认 `caching_sha2_password`，驱动需 `com.mysql:mysql-connector-j:8.0.33` |

## 6. 命名与仓库约定

- 表字段**下划线命名**，Java 属性**驼峰**，靠 `mapUnderscoreToCamelCase` 桥接（MyBatis 02 册 Step 6）。
- 包名统一 `com.groupmeal.*`；工程坐标以 `com.groupmeal` 为 groupId（历史遗留的 `org.example` 见 `javaweb-course/webdemo2/pom.xml`，属课程工程脚手架，保留不改）。
- 不进仓库的内容：`**/jdbc.properties`、`target/`、`.idea/`、`backup_*/`、以及本地环境相关的配置。
