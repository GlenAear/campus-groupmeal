# 项目选型分析 v1（2026-09-17，N2 第一阶段交付）

> 用途：今晚（9/17）闭环①「选定项目方向」的输入。你只需做一件事：**在 A / B 里选一个，回我一句话定位＋仓库名**。
> C 方案我直接给结论不展开。硬件/AI 的详细拓展设计属 N2 第二阶段，等方向定了再做。

## 1. 你手上能复用的东西（先盘点，再选型）

**网络编程课课本＝《JSP 网站开发项目化教程》，整本书就是一个"网上订餐系统"**，12 个项目正好是一条完整后端成长链：

| 课本项目 | 内容 | 对应到 Spring Boot 项目的哪一层 |
|---|---|---|
| 项目一/二 | JSP 环境搭建、静态登录/注册页、JS 校验 | 前端静态页 → 后期 Vue3 看板 |
| 项目三/四 | Servlet 逻辑验证、session 存登录用户 | 登录/鉴权 → JWT |
| 项目五/六 | cookie 免重复登录、application 计数 | 记住我、访问统计 → 统计看板 |
| 项目七 | SmartUpload 图片上传 | 文件服务模块 |
| 项目八 | 实体类/JavaBean/MVC 架构/ArrayList 存记录 | entity ＋ 分层骨架 |
| 项目九~十二 | T-SQL、JSP 连库、登录查库、增删改查 | **MyBatis mapper ＋ service（你培训刚学完的那套）** |

也就是说：**课本的每一个作业，都能直接写进你自己的项目里**，不是"另外做一份课程作业"。实验报告 1（Tomcat＋eclipse）与报告 2（JSP 内置对象）同样是这条链的环境层。

**其它资产**：暑期已配过 Tomcat、做过 Web、前后端分离；培训已学 JavaSE/MySQL/JDBC/MVC/MyBatis（后续 Spring→MVC→Boot）；硬件有掌枢繁花（ESP32＋TGAM 脑电＋手套＋莲花灯）；`D:\Java\Projects\match` 已是竞赛专用仓（算法 commit 的落点）。

## 2. 三个候选方向（五维打分，1-5）

| 维度 | A 校园拼单订餐＋智能取餐柜 | B 自习室/实验室座位预约＋能耗看板 | C 校园互助社区（失物/二手/任务） |
|---|---|---|---|
| 课程任务复用（作业/报告/大作业） | **5**（域完全一致，零额外作业） | 4（登录/预约/查改全覆盖，但上传、计数等章节要硬凑） | 2（课本无社区/消息模块，作业得另做） |
| 新颖度 | 3.5（订餐不新，但"拼单成团＋取餐柜"新） | 4 | 4.5 |
| 软硬结合可行性（V2） | **4.5**（取餐柜开锁/叫号/保温，ESP32 天然） | **5**（座位占用传感、能耗采集） | 2 |
| AI 拓展可行性（V3） | 4（拼单推荐、客服问答、营养/口味推荐） | 3.5（自习时长分析、推荐座位） | 4 |
| 比赛/简历叙事 | **4.5**（"课程项目→真实产品→软硬一体"一条线） | 4 | 3 |
| **合计** | **21.5** | 21.5 | 15.5 |

A 与 B 总分打平，但**决胜维度是"课程复用"**：你这学期最稀缺的是时间，A 能让"平时作业、两次实验报告、期末大作业、自己的 V1"**共用一个代码库**；B 需要为课程单独维护一份订餐作业，等于双线。

## 3. 我的推荐：A，并给它一个新颖的壳

**一句话定位**：宿舍楼下的"拼好饭"——同楼同学拼单成团下单食堂/周边商家，成团后统一配送到**智能取餐柜**，扫码/刷卡取餐；后期柜子接 ESP32（开锁、叫号、保温计时），再叠 AI 拼单推荐与客服问答。

- **新颖点不在"订餐"，在三件事**：①拼单成团（凑满减/凑起送，带社交裂变逻辑，课本没有）；②智能取餐柜（硬件入口，V2 的天然剧情，也是你物联网差异化的落点）；③成团算法＋推荐（AI/算法都能写进简历）。
- **课程复用**：课本项目一~十二 全部落在同一仓库（环境→登录→session/cookie→上传→实体→JDBC/MyBatis CRUD），实验报告 1/2 用它的环境层截图，期末大作业直接交它。
- **培训衔接**：MyBatis 整体重现（管线④）就用这个库做载体——重现即建项目，一次动作两笔账。
- **仓库名建议**：`campus-groupmeal`（或你喜欢的拼音 `pinhaofan`）。

**备选 B**（若你更想要"物联网差异化"的纯叙事）：座位预约＋能耗看板，硬件分最高，代价是课程作业要另维护一份订餐代码。

**C 直接否**：课程复用 2 分，意味着你这学期要同时养两个代码库，违反单一项目树红线。
